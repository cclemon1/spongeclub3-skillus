# Product Detail Page v2.4

## ACTIVATION GATE — 이 요청이면 이 스킬을 먼저 적용한다

다음 중 하나에 해당하면 **이 스킬을 우선 적용**한다.
- 사용자가 상품 사진과 함께 상세페이지 제작·설계·구조·기획을 요청함
- `상세페이지`, `상세 구조`, `전체 상세`, `판매용 상세`, `상품 상세`, `상세 기획`을 요청함
- 상품명/소재/사이즈/특징을 주고 상세 흐름이나 카피 구성을 요청함

활성화 직후 가장 먼저 `# 0. FULL-PAGE INTAKE GATE`에서 MODE A/B를 결정한다.
**MODE A라면 Ask Your Question 외의 상세 구조, 목차, 메인카피, 섹션 예시를 단 한 줄도 먼저 출력하지 않는다.**

## 목적

예쁜 페이지보다 **고객이 왜 이 상품을 사야 하는지 빠르게 이해하고, 구매 전에 필요한 정보를 충분히 확인할 수 있는 상세페이지**를 만든다.

외부 공개 스킬의 장점을 참고하되, 실제 상세페이지 레퍼런스 DB와 실무 수정 피드백을 결합해 상품 상세페이지에 맞게 재구성한다.

## 검증 범위

이 스킬은 **속옷·내의 상품으로 실제 상세페이지를 만들어 보며 검증했다.**
잠옷·홈웨어·일반 의류 규칙도 포함되어 있으나 아직 실사용 검증을 거치지 않았다.
해당 상품군에 쓸 때는 결과를 그대로 쓰지 말고 확인한 뒤 수정해서 사용한다.

# 0. 가장 먼저: FULL-PAGE INTAKE GATE

전체 상세페이지를 **처음 설계**할 때는 답변을 쓰기 전에 반드시 아래 두 모드 중 하나만 선택한다.
**한 응답에서 두 모드를 섞지 않는다.**

## MODE A — INTAKE / Ask Your Question

아래 필수 입력 중 하나라도 아직 확인되지 않았다면 이 모드다.
이 경우 답변은 `Ask Your Question`만 출력하고 즉시 끝낸다.

### INTAKE MODE에서 절대 출력하지 않는 것
- `우선 잡아둘 전체 상세페이지 구조`
- 전체 구조 / 뼈대 / 예상 목차 / 예상 섹션
- HERO, POINT, FABRIC, FIT, DETAIL 등의 임시 섹션
- 임시 메인카피 / 후킹 / 서브카피
- 이미지 구성안 / 촬영컷 계획
- 사진에서 확인되는 특징을 길게 정리한 분석
- `사진만으로도 큰 골격은 잡을 수 있다`, `일단 구조부터 잡아두겠다` 같은 선행 설명
- 질문 뒤에 붙이는 임시 상세페이지 초안

**`Ask Your Question`은 상세 구조 뒤에 붙이는 섹션이 아니다.**
질문이 필요하면 반드시 답변의 처음이자 사실상 전부여야 한다.

질문 앞에는 필요할 때만 `사진에서 확인되는 부분은 답변에 반영할게.` 정도의 짧은 한 문장을 허용한다.

### 첫 전체 상세에서 확인해야 하는 필수 입력 3그룹

이미 현재 대화·파일·사진 속 명확한 라벨에서 확인된 항목은 다시 묻지 않는다.
단, **사진만 보고 추정한 상품 분류·성별·판매 구성·소재·사이즈·정확한 컬러명은 확인된 정보로 취급하지 않는다.**

#### Q1. 상품 기본정보 — 빠진 항목만 묶어서 질문
- 정확한 상품 종류/타입
- 판매 구성: 단품 / N매 세트 / 컬러 선택형 등
- 소재 혼용률
- 사이즈 범위
- 실제 등록 컬러명 또는 컬러 운영 방식

위 항목이 여러 개 비어 있어도 각각 별도 질문 번호로 쪼개지 않고 **Q1 하나 안의 하위 항목**으로 묶는다.

#### Q2. 우선 강조 소구점 + 실제 제품 특장점
전체 상세 최초 설계에서 아직 사용자가 명시하지 않았다면 질문한다.
사용자가 `없음`이라고 답할 수 있게 한다.

- 우선 강조 소구점 / 핵심 기능 / 문제해결 포인트
  - 예: `인견 60% / 면 95% / 요실금 3중 패드 / 5매 구성 / 냉감`
- 사용자가 직접 보고·만지고·착용해 확인한 실제 특성
  - 예: `부드러움 / 얇음 / 도톰함 / 잘 늘어남 / 몸에 덜 붙음 / 가벼움 / 매끈함 / 탄탄함 / 핏 / 착용감`

**상품명이나 사진만으로 그럴듯한 소구를 추정해서 Q2를 생략하지 않는다.**
이미 사용자가 우선 소구와 실제 특성을 모두 제공했다면 다시 묻지 않는다.

#### Q3. 하단 공통 인포 준비 여부
전체 상세 최초 설계에서 아직 확인되지 않았다면 **반드시 질문한다.**
사용자가 처음 상세페이지를 만드는 경우 무엇이 필요한지 모를 수 있으므로 항목을 구체적으로 보여준다.

확인 항목:
- 실측 SIZE
- CONDITIONS: 신축성 / 비침 / 두께 / 안감 / 계절 등 회사에서 쓰는 특성표
- PRODUCT INFO / 상품고시
- NOTICE / 구매·취급 주의사항
- WASHING INFO / 세탁·관리
- 배송 안내
- 교환·반품 안내
- 고객센터 / A/S
- 기타 회사 공통 안내

`없음/모름`으로 답할 수 있게 안내한다.
일부만 준비돼 있다면 있는 항목만 알려달라고 한다.

### 질문 형식
- 한 응답에서 **번호가 붙는 질문은 최대 3개**다.
- 여러 세부값은 Q1/Q2/Q3 안의 하위 항목으로 묶는다.
- 가능하면 한 번의 INTAKE 응답에서 필요한 정보를 모두 받는다.
- 사용자가 이미 준 정보는 다시 묻지 않는다.
- 후기/VOC/인증자료는 없다고 해서 작업을 멈추지 않는다. 실제 구조에 반드시 필요한 경우에만 추가 확인한다.

기본 예시:

> ## Ask Your Question
> **Q1. 상품 기본정보 중 아직 확인되지 않은 것만 알려줘.**  
> 판매 구성 / 소재 혼용률 / 사이즈 / 실제 컬러명 등 현재 비어 있는 항목만 제시한다.  
> **Q2. 이 상품에서 꼭 앞세우고 싶은 소구점과 실제 제품 특성이 있어?**  
> 예: 인견 60%, 얇음, 부드러움, 잘 늘어남. 특별히 없으면 `없음`.  
> **Q3. 하단 공통 인포는 어디까지 준비돼 있어?**  
> `실측 SIZE / CONDITIONS / PRODUCT INFO / NOTICE / WASHING / 배송 / 교환·반품 / 고객센터·A/S` 중 있는 것만. 처음이거나 모르겠으면 `없음/모름`.

## MODE B — DESIGN / 전체 상세페이지 설계

Q1~Q3 중 현재 상품에 필요한 정보가 모두 확인되었거나 사용자가 `없음/모름`이라고 답해 처리 방향이 정해진 뒤에만 이 모드로 들어간다.

DESIGN MODE에서는 `# 17. 출력 방식`에 따라 바로 완성 설계를 출력한다.
이때 다시 `Ask Your Question`을 답변 끝에 붙이지 않는다.

## 모드 전환 규칙
- **질문이 하나라도 필요함 → MODE A만 출력 → STOP**
- **필수 질문 없음 → MODE B만 출력**
- `MODE A + 임시 구조`, `임시 구조 + Ask Your Question`, `큰 골격 먼저 + 질문` 조합은 금지한다.

## 하단 공통 인포 운용
- 기존 회사 공통 하단 인포가 있으면 새로 장문 제작하지 않고 해당 항목은 `기존 공통 인포 연결`로 처리한다.
- 일부만 있으면 있는 것은 연결하고 없는 필수 항목만 설계한다.
- 처음 만드는 경우에는 필요한 기본 하단 인포를 함께 설계한다.
- 실측값, A/S 전화번호, 회사 정책 등 실제 값이 없으면 임의 생성하지 않는다.

고객 반응 데이터가 없으면 작업을 멈추지 않는다. 내부적으로 확인된 사실 / 합리적 가설 / 추가 확인 필요를 나누되, 사용자가 요청하지 않는 한 별도 근거 상태표를 출력하지 않는다.

# 1. Evidence First: 사실과 가설을 분리한다

정보 우선순위:

1. 제품 실제 스펙
2. 사용자가 실제 제품을 직접 보고·만지고·착용해 확인한 제품 특성
   - 촉감, 두께, 유연함, 늘어남 정도, 핏, 비침, 착용감 등
3. 실제 구매후기 / Q&A / CS
4. 실제 광고 반응 / 판매 데이터
5. 사용자에게 직접 들은 고객 반응
6. 유사상품/경쟁상품 VOC
7. 일반적인 카테고리 관찰
8. 추론

추론을 사실처럼 쓰지 않는다.

근거가 약하면 내부 판단에서 다음처럼 구분한다.
- `확인됨`
- `가설`
- `추가 확인 필요`

이 상태표를 사용자에게 자동으로 보여주지 않는다. 결과물에는 필요한 경고만 최소한으로 반영한다.

효과, 성능, 건강·안전 관련 표현은 특히 보수적으로 쓴다.

## 사용자 확인 제품 특성은 실제 판매 포인트로 활용한다

사용자가 실제 제품을 직접 확인한 뒤 제공한 정보는 단순 참고가 아니라 **확인된 상품 특성**으로 취급한다.

예:
- `촉감이 부드럽다` → `부드러운 착용감`으로 활용 가능
- `원단이 유연하고 잘 늘어나는 편이다` → `움직임에 맞춰 유연하게 늘어나는 원단`으로 활용 가능
- `착용했을 때 편하다` → `편안한 착용감`으로 활용 가능
- `얇고 가볍다` → `가볍게 입기 좋은 얇은 원단`으로 활용 가능

이런 정보가 확인되면 소재 섹션을 단순히 `혼용률을 확인하세요`로 끝내지 말고,
`소재/구성 사실 → 사용자가 확인한 실제 특성 → 구매자가 체감할 장점`으로 풀어쓴다.

예:
`면 95% + 스판 5%` + 사용자가 유연함을 확인함
→ `면에 스판을 더해 움직임을 따라오는 유연함`
→ `매일 편안하게 입기 좋은 착용감`

단, **섬유 혼용률만 보고 기능을 자동 추론하지 않는다.**
- 폴리에스터 함량이 높다는 이유만으로 `신축성이 좋다`, `통기성이 좋다`, `흡습이 좋다`고 단정하지 않는다.
- 혼용률에 스판덱스/폴리우레탄이 없으면 `스판 함유`라고 쓰지 않는다.
- 스판덱스/폴리우레탄이 없어도 사용자가 실제로 원단이 잘 늘어난다고 확인했다면 `유연하게 늘어나는`, `늘어남이 있는 원단`처럼 **관찰 가능한 실제 특성**으로 표현한다.

# 2. VOC: 고객의 실제 말을 채굴한다

고객 자료가 있으면 다음을 추출한다.

- Pain: 불편/불만
- Trigger: 구매하게 된 계기
- Desired Outcome: 원하는 상태
- Objection: 망설임
- Decision Factor: 최종 선택 이유
- Exact Phrase: 고객이 실제 쓴 표현

가능하면 고객 표현을 과도하게 "광고 문구"로 번역하지 않는다.
고객이 반복해서 쓰는 단어는 섹션 제목과 카피 후보에 우선 반영한다.

리뷰가 없다면 유사상품·경쟁상품 리뷰를 보조 자료로 활용할 수 있지만,
자사 고객의 사실처럼 표현하지 않는다.

# 3. Real Why: 기능보다 구매 이유를 정한다

핵심 질문:

**"이 상품을 왜 지금, 왜 이 제품으로 사야 하는가?"**

기능을 그대로 헤드라인으로 올리지 않는다.

기본 사고:
`제품 사실 → 사용자가 실제로 확인한 특성 → 사용/착용 시 변화 → 고객에게 중요한 이유`

예:
`면 95% + 스판 5%` + 실제로 부드럽고 유연한 원단
→ `부드러운 촉감 + 움직임을 따라오는 유연함`
→ `하루 종일 입는 속옷을 더 편안하게 선택할 이유`

**MATERIAL 섹션은 가능하면 혼용률 고지에서 끝내지 않는다.**
사용자가 확인한 촉감·유연함·두께·늘어남 등의 실제 특성이 있으면 소재 수치와 연결해 구매 장점으로 풀어낸다.
반대로 실제 특성 정보가 없으면 혼용률만으로 기능을 만들어내지 않는다.

핵심 메시지는 가능하면 1개,
보조 구매 이유는 2~4개로 제한한다.

## 우선 강조 소구점 / 핵심 기능은 선택 입력값으로 둔다

상품군과 관계없이 사용자가 특별히 앞세우고 싶은 구매 이유가 있다면 **`우선 강조 소구점`**으로 취급한다.

예:
- 요실금 팬티 → `요실금 대응 / 흡수 구조`
- 발열내의 → `발열·보온 기능`
- 냉감 잠옷 → `시원한 착용감 / 냉감 원단`
- 인견 잠옷 → `인견 고함량`
- 면 95% 팬티 → `높은 면 함유율`
- 수유 잠옷 → `수유가 편한 구조`
- 보정 의류 → `복부/라인 보정`
- 세트 상품 → `구성 가성비`

운용 원칙:
- 특정 상품군을 `기능성 속옷`처럼 좁게 분류해서 적용하지 않는다. 속옷·내의·잠옷·홈웨어·일반 의류 모두 사용할 수 있다.
- 사용자가 우선 강조 소구점을 제공하면 초반 HOOK/핵심 포인트/추천 대상 섹션의 우선순위를 높여 배치한다.
- 우선 소구점이 없으면 해당 입력은 **패스**한다. 빈칸을 채우려고 억지 차별점을 만들지 않는다.
- 상품명이나 제공 정보만으로 핵심 기능이 명확하면 다시 질문하지 않는다.
- 객관적 성능이 필요한 기능은 시험자료·제품 스펙·사용자 확인 정보 범위 안에서만 표현한다.
- 질환 치료·개선·예방처럼 의료적 효과로 확장하지 않는다.

## 선호 소재·고함량 소재는 구매포인트 우선순위를 높인다

고객이 소재 자체를 구매 기준으로 보는 카테고리에서는 **선호도가 높은 소재와 높은 함유율을 강하게 보여준다.**

예:
- 면 95%
- 모달 고함량
- 인견 고함량
- 텐셀/레이온 등 사용자가 선호하는 소재

원칙:
- `COTTON 95%`, `MODAL 90%`처럼 **실제 혼용률 숫자 자체를 메인 소구로 사용할 수 있다.**
- 100%가 아니면 `순면`, `100% 면`처럼 오해할 수 있는 표현은 쓰지 않는다.
- 면 95% + 스판 5%처럼 선호 소재에 소량의 스판이 섞인 경우, 실제 특성이 확인되었다면 `높은 면 함유율 + 움직임을 돕는 유연함`처럼 두 장점을 함께 연결한다.
- 소재 이름만으로 통기성·흡습성·보온성·냉감 등 객관적 기능을 자동 추론하지 않는다.
- 같은 상품에서 여러 장점이 있어도 **선호 소재 함유율이 구매결정에 중요한 상품이면 초반 핵심 포인트에 우선 배치한다.**

# 4. 상세페이지 공통 구성 원칙

## `이런 분께 추천드려요`는 기본 필수 모듈

전체 상세페이지 기획에는 **`이런 분께 추천드려요` 또는 같은 역할의 추천 대상 섹션을 반드시 포함한다.**
단, 사용자가 명시적으로 제외했거나 확인된 정보만으로 추천 대상을 안전하게 작성할 수 없는 경우에만 생략한다.

배치 기준:
- 일반 속옷·잠옷·의류 → 핵심 포인트를 충분히 보여준 뒤 중간~하단에 배치 가능
- 요실금 팬티, 발열내의, 냉감·보정·기능성 등 **문제해결형/기능성 제품** → `HOOK/핵심 포인트 또는 핵심 기능 설명 직후`, COLOR/DETAIL보다 앞쪽에 배치한다.
- 타깃이 너무 일반적이면 억지로 과장된 고민을 만들지 말고 `이런 분께 잘 맞아요` 수준의 실제 사용상황으로 작성
- 확인되지 않은 질환·치료·개선 효과를 추천 문구에 넣지 않는다.

## 포인트 이후의 기본 이미지 흐름

전체 상세페이지에서 다음 흐름을 우선 검토한다.

`핵심 포인트 → 이런 분께 추천 → 컬러/디자인 확인 → 디테일컷 → 하단 구매정보`

단, 상품 특성상 소재·기능 설명이 더 중요하면 순서를 앞당길 수 있다.

### 컬러/디자인 컷
- **컬러별 바닥컷·정면컷·구성컷이 제공되었거나 제작 가능한 경우 COLOR/DESIGN VIEW는 DETAIL보다 먼저 배치한다.** 사용자가 다른 순서를 명시한 경우만 예외로 한다.
- 속옷의 일반적인 `허리밴드 / 프런트 봉제 / 밑단 봉제 / 안쪽 덧댐 / FRONT·BACK 제품 확인`은 각각 별도 섹션으로 쪼개지 않고 **기본적으로 하나의 DETAIL 섹션에 묶는다.** 특정 디테일이 실제 핵심 소구점일 때만 독립 섹션으로 분리한다.
- `PRODUCT VIEW`, `FRONT/BACK`, `WAIST`, `FRONT PATTERN`, `HEM`처럼 **새 구매 이유 없이 제품을 확인하는 역할이 같은 항목은 DETAIL 안의 이미지 묶음으로 처리**한다.
- 위쪽에서 이미 설명한 디테일을 후반에 다시 보여줄 때는 다른 컬러·더 큰 확대·정확한 제품 확인이라는 역할이 있을 때 이미지 위주로 재노출하고 같은 설명을 반복하지 않는다.
- 사용자가 다른 순서를 명시했거나 컬러 확인용 이미지가 전혀 없는 경우만 예외로 한다.
- 컬러명이나 패턴명을 모르면 임의로 이름을 만들지 않고 이미지로 보여준다.
- `컬러 바닥컷 → 디테일컷`은 속옷·잠옷·의류에서 실제 상품 확인 흐름의 기본값으로 본다.

### 디테일컷
- 속옷: 허리밴드 / 다리둘레 마감 / 안쪽 덧댐 / 리본·프린트 등
- 잠옷·의류: 넥 / 소매 / 포켓 / 밑단 / 봉제 / 단추 등 실제 구매에 필요한 디테일
- 위쪽 핵심 포인트에서 이미 충분히 설명한 디테일은 아래에서 같은 문장으로 반복하지 않는다.
- 단, **다른 컬러의 확대컷, 더 큰 배율, 더 명확한 제품 확인용 이미지**라면 설명 없이 또는 짧은 라벨만 붙여 다시 보여줘도 된다.
- 따라서 `중복 이미지 = 삭제`가 아니라, **이미지 역할이 달라지는지**를 기준으로 판단한다.
- 요실금/흡수팬티처럼 안쪽 패드가 이미 핵심 기능 섹션에서 충분히 설명되었다면 `안쪽 구조`를 또 독립 섹션으로 만들지 않는다. 후반 DETAIL에서는 다른 컬러·확대·전체 구조 확인용 이미지로만 재노출할 수 있다.
- `FIT / SHAPE / TYPE` 같은 섹션은 **제품 형태 자체가 구매 결정에 영향을 주는 차별점일 때만** 만든다. 일반적인 드로즈·팬티·런닝 형태를 설명하기 위해 억지로 독립 섹션을 만들지 않는다.

## 진한 색상 제품의 세탁 주의

속옷·잠옷·의류에 블랙, 네이비, 다크브라운 등 진한 색상이 포함된 경우, 브랜드/제품 세탁 기준과 충돌하지 않는 범위에서 하단 세탁정보 외에 한 번 더 눈에 띄게 안내한다.

기본 주의 문구 예:
- `진한 색상은 단독 세탁을 권장합니다.`
- `건조기 사용은 피해주세요.`

제품 케어라벨이나 브랜드 공통 세탁 지침에 다른 기준이 있으면 그 기준을 우선한다.

## 하단 구매정보는 `상품별 정보`와 `회사 공통 정보`로 나눠 관리한다

회사마다 디자인과 명칭은 달라도, 의류/속옷 상세페이지 하단은 대체로 아래 모듈을 조합한다.

기본 후보 순서:

`(선택) MODEL SIZE → SIZE/실측 → CONDITIONS → PRODUCT INFO → NOTICE → WASHING INFO → (선택) 브랜드 공통안내/저작권 → 배송 → 교환·반품 → 고객센터/A/S`

모듈 설명:
- `MODEL SIZE` : 모델 신장/체형/착용 사이즈. 착용컷이 있고 정보가 있을 때만.
- `SIZE/실측` : 제품 실측표 또는 확인된 사이즈 옵션.
- `CONDITIONS` : 신축성·비침·두께·안감·계절 등 상품군별 체크 정보. 확인된 값만 표기.
- `PRODUCT INFO` : 구성, 소재, 컬러, 사이즈, 제조국, 제조사 등 상품별 고시/기본정보. 회사 운영 기준에 따라 **품질보증기준, A/S 안내, A/S 전화번호**까지 확인한다. 교환·반품이 별도 하단 공통 영역에 있으면 PRODUCT INFO에서 중복하지 않아도 된다.
- `NOTICE` : 측정오차, 모니터 색상차, 원단/프린트 특성 등 구매·취급 주의. 실제 적용되는 내용만.
- `WASHING INFO` : 세탁방법, 건조기/다림질/표백 등 관리정보. 케어라벨·브랜드 기준 우선.
- `배송 / 교환·반품 / 고객센터/A/S` : 회사 공통 정책 영역.
- `저작권·브랜드 공통 안내` : 회사에서 운영 중일 때만 연결.

운용 규칙:
- 회사에서 이미 해당 모듈 디자인이 준비되어 있으면 **새로 다시 만들지 않고 `기존 공통 인포 연결`로 처리한다.**
- 일부만 준비되어 있으면 **준비된 것은 연결하고, 빠진 필수 정보만 설계한다.**
- 처음 상세페이지를 만드는 사용자에게는 어떤 하단 인포가 필요한지 스킬이 먼저 구체적으로 안내하고 확인한다.
- 사용자가 `없음/모름`이라고 답하면, 상품군에 필요한 기본 모듈을 스킬이 제안·설계한다.
- 모든 회사에 모든 모듈을 강제하지 않는다. 상품군/운영 방식에 따라 선택한다.
- 실측 데이터나 CONDITIONS 값이 없으면 임의 수치·체크값을 만들지 않는다.
- 배송/교환·반품/고객센터 같은 회사 정책은 사용자가 제공하지 않으면 임의로 만들어내지 않고 `회사 정책 입력 필요`로 표시한다.

- **A/S 전화번호는 실제 번호가 확인되어야 한다.** 번호를 모르면 임의로 만들지 말고 `A/S 연락처 확인 필요`로 표시하거나 Ask Your Question에서 확인한다.
- 품질보증기준도 회사 공통 기준이 있으면 그 기준을 연결하고, 없으면 `품질보증기준 확인 필요`로 표시한다.
- 하단 기본 순서는 아래를 우선한다. 선택 모듈은 필요한 경우에만 끼워 넣는다.  
  `MODEL SIZE(선택) → SIZE/실측 → CONDITIONS(선택) → PRODUCT INFO → NOTICE(선택) → WASHING INFO → 배송 → 교환·반품 → 고객센터/A/S`
- 사용자가 이미 회사 공통 하단 디자인을 갖고 있다면 위 내용을 새로 장문 작성하지 않고 `기존 공통 인포 연결`로 표시한다.

# 5. 상품군을 먼저 분기한다

## A. 속옷 / 내의

속옷은 **성인/주니어 또는 남성/여성만으로 규칙을 나누지 않고 제품 구조를 먼저 본다.**
주니어 드로즈와 성인 드로즈는 기본적으로 같은 `하의형 드로즈` 구조이며, 차이는 사이즈 체계·타깃 정보에서 처리한다.

우선 검토:
- 촉감
- 선호 소재 함유율
- 유연함/늘어남/움직임
- 두께감·몸에 붙는 느낌 등 사용자가 확인한 착용 특성
- 허리밴드
- 밑단/봉제
- 안쪽 마감
- 체형/사이즈
- 컬러/세트
- 세탁/관리
- 기능성/패드/보정 구조가 있으면 해당 기능

기본 구조 후보:
`HOOK → 핵심 포인트 → (기능성/문제해결형이면 이런 분께 추천 상단) → 소재/착용감 → 일반 상품이면 이런 분께 추천 → 컬러/디자인 바닥컷 → 디테일 → SIZE/실측 → PRODUCT INFO → WASHING/배송/교환·반품/A/S`

속옷은 연출컷만 길게 보여주지 않는다.
몸에 닿는 느낌과 구매 불안을 해소하는 정보 비중을 높인다.

### A-1. 하의형 속옷
대상 예:
- 여성 팬티
- 브리프
- 남성/주니어 드로즈
- 트렁크/복서브리프
- 요실금·흡수·보정 팬티의 기본 하의 구조

**성인/주니어를 별도 구조로 나누지 않는다.**
제품 형태가 같으면 같은 실측·디테일 원칙을 쓰고 사이즈 값만 달라진다.

실측 항목 후보:
- 여성 팬티: `허리단면 / 힙단면 / 총장`
- 드로즈·복서브리프: `허리단면 / 총길이 / 밑단면`
- 제품 구조상 필요하면 `힙단면 / 밑위 / 옆선 길이` 등을 추가 가능

실측 운용:
- 회사에서 쓰는 기존 실측 도식·측정법이 있으면 그것을 최우선으로 사용한다.
- 값이 없으면 수치를 만들지 않는다.
- 값이 없더라도 설계안에는 `실측 필요 항목: 허리단면 / 총길이 / 밑단면`처럼 **어떤 항목이 필요한지 예시를 보여준다.**
- `L / XL / 2XL` 같은 호칭 사이즈만 있는 경우 공식 신체사이즈 참고표가 있으면 함께 제공 가능하다.
- **권장 체중은 기본적으로 지양한다.** 같은 몸무게라도 체형 차이가 크기 때문이다.

### A-2. 상의형 속옷
대상 예:
- 런닝
- 캐미솔
- 브라탑
- 민소매 이너

실측 항목 후보:
- `가슴단면 / 총장 / 밑단단면`
- 제품에 따라 `어깨폭 / 암홀 / 끈 길이` 추가

제품 구조에 맞지 않는 항목을 억지로 넣지 않는다.
기존 회사 실측 도식이 있으면 그 도식을 우선한다.

### A-3. 브라형
대상 예:
- 브라
- 노와이어 브라
- 패드 브라

우선 확인:
- 사이즈 체계(컵/언더 등)
- 와이어/노와이어
- 패드 유무·탈착 여부
- 후크 구조
- 어깨끈 조절 여부
- 밴드/날개 구조
- 공식 사이즈 가이드

브라 사이즈와 컵 호환 범위를 임의로 추정하지 않는다.
회사 공식 사이즈표가 있으면 우선 사용하고, 없으면 필요한 정보만 질문한다.

### A-4. 기능 오버레이
요실금·흡수·보정·기타 문제해결형 속옷은 **별개의 전체 구조가 아니라 기본 제품 구조 + 기능 오버레이**로 처리한다.

예:
- 요실금 팬티 = 하의형 팬티 구조 + `요실금/패드` 기능
- 보정 팬티 = 하의형 팬티 구조 + `보정` 기능
- 기능성 브라 = 브라형 구조 + 확인된 기능

기능성/문제해결형 원칙:
- 우선 강조 소구를 초반에 명확히 보여준다.
- `이런 분께 추천드려요`를 상단에 배치한다.
- 패드/기능 구조는 확인된 사실만 설명한다.
- 흡수량(cc), 방수, 냄새 억제, 항균, 의료효과 등은 실제 자료가 없으면 쓰지 않는다.
- 패드 기능을 앞에서 충분히 설명했다면 후반에 `안쪽 구조`를 별도 섹션으로 중복 생성하지 않는다.

### 반복 입력을 줄이기 위한 기본값 — 일반 봉제형 여성 팬티

사용자가 일반적인 **봉제형 여성 팬티**를 작업하고 있고, 상품명·사진·제공 정보에 반대 근거가 없으면 아래 항목은 반복 질문 없이 기본값으로 사용할 수 있다.

- 허리: `밴드형`
- 다리둘레: `박음질 마감`
- 안쪽: `이중 덧댐 처리`

운용 원칙:
- 이 기본값은 **일반 봉제형 여성 팬티에만** 우선 적용한다.
- `누디 / 노라인 / 심리스 / 무봉제 / 레이저컷` 등 구조가 다른 상품은 기본값을 자동 해제한다.
- 제품 사진에서 다른 구조가 명확하게 보이거나 사용자가 다른 정보를 제공하면 사용자 정보와 실제 제품이 항상 우선한다.
- 다른 하위 상품군의 기본값은 지금 임의로 만들지 않는다. 실제 작업에서 반복 검증될 때 추가한다.

### 속옷 이미지 흐름
- 핵심 소구/소재/기능
- `이런 분께 추천드려요`
- 컬러별 바닥컷·정면컷
- 디테일 확대
- 사이즈/실측
- 하단 인포

상단에서 설명한 디테일을 후반에 다시 보여줄 때는 **다른 컬러·더 큰 확대·정확한 실물 확인**이라는 새로운 이미지 역할이 있을 때 허용한다.

## B. 잠옷 / 홈웨어

> 아래 규칙은 아직 실사용 검증을 거치지 않았다. 결과를 확인하고 수정해서 사용한다.

우선 검토:
- 전체 무드
- 착용 이미지
- 계절감

# 7. 후킹: 같은 말 3번 금지

후킹 3안을 요청받으면 **서로 다른 진입각도**로 만든다.

가능한 각도:
- 고객 대사형
- 문제제기형
- 손실/불편형
- 관찰형
- 통념 뒤집기형
- 소재/숫자 대비형
- 사용 상황형
- 결과/변화형
- 타깃 저격형

기본 출력:

| 방향 | 메인 후킹 | 추천 |
|---|---|:---:|
| 진입각도 1 | 카피 | ★★★ |
| 진입각도 2 | 카피 | ★★☆ |
| 진입각도 3 | 카피 | ★★☆ |

후킹 3안은 서로 다른 진입각도로 만든다.

표 아래에 최종 추천 1개와 추천 이유를 1~2문장으로 덧붙인다.

`노리는 효과`, `리스크`는 실제 판단에 필요한 경우에만 추가하며 기본 출력에서는 생략한다.

후킹만 자극적이고 제품 가치가 뒤에 없으면 버린다.

## 메인카피는 짧고 상품 고유 포인트가 먼저 보이게 한다

메인카피/후킹은 가능하면 **1~2줄, 한 가지 핵심 메시지**로 쓴다.

우선순위:
1. 상품을 고르게 만드는 강한 사실: `인견 60% / 면 95% / 3중 패드 / 5매 구성` 등
2. 실제 확인된 착용 특성: 얇음, 부드러움, 잘 늘어남, 몸에 덜 붙음 등
3. 감성 표현

강한 소재·기능·숫자 소구가 있는데도 `가볍게 닿고 편안하게`, `부담은 덜고 일상은 편안하게`처럼 **다른 상품에도 그대로 붙일 수 있는 범용 문구를 메인으로 먼저 쓰지 않는다.**

예:
- `인견 60% / 얇고 부드러운 드로즈`
- `면 95% / 부드러움에 유연함을 더한 팬티`
- `3중 패드 / 인견 95% 요실금 팬티`

위 예시는 형식 참고용이며 실제 상품 정보에 맞춰 작성한다.

### 쉼표 사용
쉼표 자체를 금지하지 않는다.
다만 AI식으로 `A하게, B하게`, `A도, B도`, `부드럽게, 편안하게`처럼 **병렬 감성어를 습관적으로 연결하는 패턴**을 기본값으로 사용하지 않는다.
쉼표 없이 더 짧고 직접적으로 말할 수 있으면 그쪽을 우선한다.

# 8. 본문 카피 규칙

## 기본 원칙
- 명확함 > 재치
- 한 섹션 = 한 중심 메시지
- 기능 나열보다 고객에게 생기는 변화
- 추상어보다 구체적인 상황
- 과장보다 사실
- 고객이 이해하는 쉬운 말
- **반복 자체를 금지하지 않는다. 읽는 흐름에서 불필요하게 겹치는 반복만 줄인다.**

## 기본 형식
`짧은 제목`
`핵심 장점`
`구매 설득 문장`

### 섹션 이름은 실제 구매 이유가 있을 때만 만든다
`FIT / SHAPE / TYPE / INTRO / WHY` 같은 이름은 템플릿 채우기용으로 자동 생성하지 않는다.
상품에서 실제로 설명할 차별점·이미지 역할·구매정보가 있을 때만 사용한다.
일반적인 제품 형태를 말하기 위해 `기본 드로즈 핏`, `일반 미디 타입` 같은 독립 섹션을 억지로 만들지 않는다.

필요하면:
`근거 / 스펙 / 디테일`

## 카피 반복 운용 규칙
상세페이지는 핵심 장점을 기억시키기 위해 **의도적인 반복을 허용**한다.
목표는 중복을 없애는 것이 아니라, **새 정보 없이 바로 이어지는 반복을 줄이는 것**이다.

출력 전 `카피 반복 점검`을 수행하되, 삭제보다 **거리·역할·표현의 차이**를 먼저 본다.

### 1) 기본 모드: AUTO
사용자가 별도 지시하지 않으면 상품의 소구점 수와 정보량을 보고 반복 강도를 자동 조절한다.

- 소구점이 많은 상품 → 다양한 포인트를 우선 배치하고 같은 표현의 근접 반복을 줄인다.
- 소구점이 보통인 상품 → 핵심 장점을 필요에 따라 다시 언급할 수 있다.
- 소구점이 적은 상품 → 같은 핵심 장점을 초반·중간·후반에서 **다른 표현·상황·근거**로 반복해도 된다.

사용자가 원하면 다음 모드를 직접 지정할 수 있다.
- `DIVERSE` : 가능한 한 여러 소구점을 넓게 사용
- `BALANCED` : 핵심 장점의 자연스러운 반복을 허용
- `FOCUSED` : 소구점이 적을 때 핵심 장점을 여러 각도로 반복

모드는 내부 운용 기준이며, 사용자가 요청하지 않으면 결과에 모드 설명을 따로 출력하지 않는다.

### 2) 반복을 허용하는 경우
다음은 같은 의미 축이어도 허용한다.
- 초반 HOOK에서 장점을 먼저 제시하고, 중간 섹션에서 실제 근거나 제품 특성으로 다시 설명하는 경우
- 초반에 감성적으로 말하고, 후반에 정보형 문장으로 다시 확인시키는 경우
- 같은 핵심 장점을 사용 상황 / 소재 근거 / 착용 결과처럼 **역할을 달리해** 설명하는 경우
- `편안함`, `유연함`, `5매`, `미디형`처럼 상품 이해에 필요한 핵심 단어를 자연스럽게 다시 쓰는 경우
- PRODUCT INFO에서 앞서 나온 사실 정보를 최종 확인용으로 다시 표기하는 경우

예:
- HOOK: `편안함을 먼저 생각한 데일리 팬티`
- FABRIC: `유연하게 늘어나는 원단`
- 후반 카피: `움직일 때 부담을 덜어주는 착용감`

같은 `편안함` 축이지만 위치와 역할이 다르므로 허용한다.

### 3) 우선 정리하는 반복
다음처럼 **가까운 위치에서 새 정보 없이 같은 말을 재포장**하면 수정한다.
- `매일 입기 좋은` → 바로 다음 섹션에서 `데일리로 입기 좋은`
- `부담 없이 손이 가는` → 이어서 `편하게 자주 입는`
- `깔끔한 마감` → 같은 디테일 설명에서 `정돈된 마감`

`매일`, `데일리`, `편안함`, `깔끔하게` 같은 범용어도 **횟수 자체로 금지하지 않는다.**
다만 제목·핵심카피에서 짧은 구간에 연달아 반복되어 눈에 띄면 하나 이상을 다른 표현으로 조정한다.

### 4) 섹션별 구매포인트를 강제하지 않는다
각 섹션이 반드시 서로 다른 구매포인트를 가져야 하는 것은 아니다.

- 같은 핵심 소구점을 여러 섹션에서 다뤄도 된다.
- 단, 각 섹션은 가능하면 **새로운 근거, 새로운 시각, 새로운 이미지 역할, 새로운 구매정보** 중 하나를 더한다.
- `SET`, `DESIGN`, `FABRIC`, `COMFORT`, `TYPE`, `DETAIL` 등은 참고용 역할 구분일 뿐 강제 배정표가 아니다.
- 소구점이 적은 상품은 억지로 차별점을 만들지 말고, 핵심 장점을 자연스럽게 확장한다.

### 5) 풀 내용이 없을 때
- 문장을 억지로 늘리지 않는다.
- 비슷한 내용을 가진 `INTRO`, `WHY`, `DESIGN VIEW`라도 **이미지 흐름, 감성 전환, 구매 확인 역할**이 있으면 유지할 수 있다.
- 삭제·병합은 자동 규칙이 아니라 선택지다.
- 짧게 가는 편이 좋을 때만 압축하고, 상품의 분위기나 디자인 전개가 필요하면 충분히 풀어도 된다.

### 6) 최종 문장 점검
출력 직전에 제목·핵심문장·보조문장을 훑어 다음만 확인한다.
- 바로 앞뒤에서 거의 같은 표현이 반복되는가?
- 같은 문장을 조금만 바꿔 연속 재진술하고 있는가?
- 반복이 의도적인가, 아니면 단순한 카피 부족 때문인가?

의도와 역할이 있으면 유지한다. 불필요한 근접 반복만 수정한다.

## 3안 제안 시
같은 문장을 어미만 바꾸지 않는다.

예:
- 기본안
- 감성안
- 판매전환안

또는
- 문제해결형
- 사용상황형
- 소재근거형

- 큰 주름
- 먼지/오염

- 피부/의류 핏의 아주 작은 보정

**"원본 제품을 보존한 채 환경을 연출한다"**는 기준으로 작업한다.

- 프로젝트 맥락 설명(`OO 톤으로`, `OO 브랜드에 맞게`)도 사용자가 요청하지 않으면 결과에 쓰지 않는다.

# 17. 출력 방식

사용자가 전체 상세페이지 기획을 요청하면 **읽는 기획서가 아니라 바로 제작에 사용할 수 있는 압축 설계도**로 출력한다.

## 최우선 원칙

- 이 출력 형식은 **MODE B — DESIGN에서만** 사용한다. MODE A — INTAKE에서는 이 절의 어떤 표·구조·후킹도 출력하지 않는다.
- `Ask Your Question`이 필요한 응답과 `전체 상세페이지 설계도`를 같은 답변에 함께 넣지 않는다.
- 전체 상세페이지 기획의 기본 출력은 아래 **6개 블록만** 사용한다.
- 서론, 근거 상태표, 내부 분석 과정, 타깃 추론 설명, 마지막 종합 해설은 붙이지 않는다.
- 같은 정보를 **바로 이어서 새 정보 없이 반복 설명하지 않는다.** 다만 핵심 장점을 초반에 제시하고 후반에 근거·상황·정보로 다시 풀어내는 반복은 허용한다.
- 출력 전 제목·핵심문장·보조문장에 대해 `카피 반복 점검`을 수행하되, 의미가 비슷하다는 이유만으로 자동 삭제하지 않는다.
- `매일/데일리/편안함/부담 없이/깔끔하게/기본` 같은 범용어는 횟수 제한을 두지 않는다. 다만 짧은 구간에 연속 반복되어 눈에 띄면 표현을 분산한다.
- 표와 짧은 문장 위주로 작성한다.
- 사용자가 요청하지 않은 레이아웃 해설, 섹션 역할 설명, 주의문을 반복하지 않는다.
- 미확인 정보는 임의로 채우지 않는다.
- **사용자가 직접 확인한 촉감·유연함·늘어남·핏·착용감은 판매 포인트로 적극 활용하되, 그 때문에 섹션 수나 설명량을 늘리지 않는다.**

## 출력 전 반드시 하는 `섹션 압축` 판단

전체 구조를 출력하기 전에 비슷한 메시지를 자동으로 합친다.

- **6~8개는 권장 범위일 뿐 강제하지 않는다.** 상품 정보량, 이미지 수, 디자인 전개에 따라 더 짧거나 길어질 수 있다.
- 10개 이상이어도 각 섹션이 정보·이미지·리듬상 역할이 있으면 유지할 수 있다.
- 작은 디테일은 보통 묶는 편이 효율적이지만, 실제 구매 판단에 중요하거나 사진 설명력이 충분하면 독립 섹션으로 둘 수 있다.
- 여러 섹션이 같은 핵심 소구점을 공유해도 된다. 각 섹션은 새로운 근거·상황·이미지 역할·구매정보 중 하나를 더하는 것을 우선한다.

병합은 **선택 기준**으로 사용한다.
- `MATERIAL + COMFORT` → 한 번에 설명하는 편이 더 자연스러울 때 병합 가능
- `WAIST + FRONT + HEM + INNER DETAIL + PRODUCT VIEW` → 일반적인 제품 확인 디테일이라면 **기본적으로 `DETAIL` 하나로 묶는다.** 특정 항목이 실제 핵심 소구점일 때만 분리한다.
- `COLOR + SET` → 컬러와 구성을 함께 보는 편이 자연스러울 때 병합 가능
- `5 PIECES + DESIGN` → 구성과 디자인을 한 흐름으로 보여주는 편이 좋을 때 병합 가능
- 비슷한 이미지가 반복되더라도 초반 감성컷 / 후반 정확한 제품 확인처럼 역할이 다르면 유지 가능

**새 섹션을 만드는 기준:**
구매정보뿐 아니라 감성 전환, 이미지 리듬, 제품 확인, 근거 제시 중 하나라도 명확한 역할이 있으면 만들 수 있다.  
다만 단순히 분량을 늘리기 위한 섹션은 만들지 않는다.

## 1. 전체 상세페이지 설계도

가장 먼저 페이지 전체 흐름을 아래 **정확한 4열 표**로 보여준다. 열을 추가하지 않는다.

| 순서 | 섹션 | 전달할 핵심 | 메인 이미지 |
|---|---|---|---|
| 01 | HOOK | 첫 구매 이유 | 대표 제품컷 |
| 02 | WHY | 핵심 장점 요약 | 포인트 이미지 |
| 03 | FABRIC & COMFORT | 소재와 착용 장점 | 원단/착용 포인트 |
| ... | ... | ... | ... |

규칙:
- 상품에 필요한 섹션만 사용한다.
- 6~8개를 권장하되 상품과 이미지 흐름에 따라 유연하게 조정한다.
- 각 셀은 한 줄 중심으로 짧게 쓴다.
- 이 표만 봐도 상세페이지 전체 흐름이 이해되어야 한다.
- 전체 상세페이지에는 `이런 분께 추천드려요` 역할의 섹션을 **반드시 포함한다.** 기능성/문제해결형이면 `HOOK/핵심 포인트 또는 기능 설명 직후`, COLOR/DETAIL보다 앞에 배치한다. 일반 상품이면 중간~하단 배치 가능하다.
- 컬러별 바닥컷·정면컷·구성컷이 제공되었거나 제작 가능하면 `COLOR/DESIGN VIEW`를 `DETAIL`보다 먼저 배치한다.
- FIT/SHAPE/TYPE은 실제 구매 차별점이 있을 때만 만든다.
- 하단 정보는 회사 운영 방식에 따라 `MODEL SIZE(선택) → SIZE/실측 → CONDITIONS → PRODUCT INFO → NOTICE → WASHING INFO → 배송 → 교환·반품 → 고객센터/A/S` 후보 순서를 검토한다.
- 회사 공통 인포 디자인이 이미 준비되어 있으면 해당 모듈은 새로 설계하지 않고 `기존 공통 인포 연결`로 표시한다.
- 일부만 준비되어 있으면 준비된 모듈과 새로 설계할 모듈을 구분해서 보여준다.
- `PRODUCT INFO`에는 확인된 소재·컬러·사이즈·구성 등 최종 구매정보를 정리한다. 회사 공통 인포에서 별도로 처리하지 않는 경우 **`품질보증기준 → A/S 안내 → A/S 전화번호`를 반드시 체크**한다.
  - 실제 값이 있으면 그대로 표기한다.
  - 값이 없으면 항목 자체를 삭제하지 말고 `확인 필요`로 표시하거나 Ask Your Question에서 확인한다.
  - 하단 공통 A/S/고객센터 영역이 이미 준비되어 있으면 중복 표기 대신 `기존 공통 A/S 인포 연결`로 표시할 수 있다.
  - 교환·반품이 별도 하단 공통 영역에 있으면 PRODUCT INFO에서 중복하지 않아도 된다.
  - A/S 전화번호는 절대 임의 생성하지 않는다.

## 2. 후킹 3안

아래 **정확한 3열 표**를 사용한다. 열을 추가하지 않는다.

| 방향 | 메인 후킹 | 추천 |
|---|---|:---:|
| 진입각도 1 | 카피 | ★★★ |
| 진입각도 2 | 카피 | ★★☆ |
| 진입각도 3 | 카피 | ★★☆ |

표 아래에는 다음만 쓴다.
- `추천: OOO형`
- 추천 이유 1문장

그 외 장단점, 리스크, 전략 설명은 요청이 없으면 쓰지 않는다.

## 3. 섹션별 제작안

각 섹션은 **반드시 아래 4행 표 형식**을 기본으로 사용한다. 표 아래에 장문 설명을 붙이지 않는다.

### 01. SECTION NAME

| 항목 | 내용 |
|---|---|
| **제목** | 실제 사용할 제목 |
| **핵심 문장** | 가장 중요한 메시지 1개 |
| **보조 문장** | 필요할 때만 1~2문장 |
| **이미지** | ⭐ 필수 / ○ 선택 |

규칙:
- 한 섹션당 표 1개를 기본으로 한다.
- `레이아웃`, `이 섹션 역할`, `기획 의도`, `왜 필요한지`를 기본 출력하지 않는다.
- 표 아래 추가 설명은 원칙적으로 붙이지 않는다.
- 법적/근거상 꼭 필요한 경고만 `⚠️ 한 줄`로 추가할 수 있다.
- 같은 소재·장점·핵심 키워드를 여러 섹션에서 다시 사용할 수 있다. 다만 바로 앞뒤에서 새 정보 없이 반복하지 않는다.
- 의미가 비슷해도 역할이 다르면 허용한다. 예: 초반 `편안함` 후킹 → 중간 `유연한 원단` 근거 → 후반 `움직일 때 부담을 덜어주는 착용감`.
- 섹션 제목과 핵심문장이 반드시 서로 다른 구매포인트일 필요는 없다. 상품 소구점이 적으면 같은 핵심 축을 다른 표현과 시각으로 확장할 수 있다.
- **사용자 확인 특성 → 구매 장점**은 HOOK/근거 섹션/후반 확인 구간에서 필요에 따라 다시 사용할 수 있다.
- `유연하게 잘 늘어남 + 편안한 착용감`은 한 섹션으로 묶어도 되고, 이미지와 정보가 충분하면 FABRIC과 COMFORT로 나눠도 된다.
- 사이즈 섹션은 단순 옵션 나열로 끝내기보다 해당 상품 구조에 맞는 **실측 항목**을 우선 제안한다. 값이 없으면 예시 항목만 보여주고 수치는 만들지 않는다.
- 하의형 드로즈 예: `허리단면 / 총길이 / 밑단면`
- 여성 팬티 예: `허리단면 / 힙단면 / 총장`
- 상의형 속옷 예: `가슴단면 / 총장 / 밑단단면` + 구조에 따라 암홀/어깨/끈
- 권장 체중은 기본적으로 제안하지 않는다.
- 허리밴드/다리둘레/안쪽 덧댐도 한 DETAIL로 묶을 수 있지만, 각 사진과 설명 가치가 충분하면 개별 구간으로 풀어도 된다.
- 이미지 제안은 1~3개로 제한한다.
- 면·모달·인견 등 선호 소재가 고함량이면 소재 수치 자체를 핵심 타이틀/포인트로 적극 활용한다.
- `이런 분께 추천드려요` 섹션은 기본 포함하되, 상품 성격에 따라 상단 또는 중하단에 배치한다.
- 위에서 이미 설명한 디테일이라도 다른 컬러·더 큰 확대·제품 확인 목적의 이미지라면 후반 디테일컷에서 설명 없이 재노출할 수 있다.
- **사용자가 제공하지 않았거나 존재 여부가 확인되지 않은 자료를 `⭐ 필수` 이미지로 요구하지 않는다.**
- 예: 실측표가 없으면 `실측 사이즈표`를 필수로 쓰지 말고, 확인된 사이즈 옵션 `85 / 90 / 95 / 100`을 보여주는 간단한 사이즈 안내로 대체한다.
- 후기 캡처, 인증서, 시험성적서, 체형별 권장표 등도 실제 자료가 있을 때만 이미지/섹션에 포함한다.
- 제목/핵심/보조 문장은 실제 상세페이지에 바로 복사할 수 있는 수준으로 쓴다.

## 4. 이미지 준비 체크리스트

### 🔴 꼭 필요한 이미지
- ☑ 이미지
- ☑ 이미지
- ☑ 이미지

### 🟡 있으면 좋은 이미지
- □ 이미지
- □ 이미지
- □ 이미지

규칙:
- 필수와 선택만 구분한다.
- 섹션에서 언급한 이미지를 제작 체크용으로 한 번 모으는 것은 허용한다.
- 비슷한 역할의 이미지를 중복 요구하지 않는다.
- **현재 보유 여부가 확인되지 않은 원자료·증빙·실측 데이터는 `꼭 필요한 이미지`에 넣지 않는다.**
- 없는 자료가 있으면 새로 만들어야 할 필수물처럼 표현하지 말고, 확인된 정보로 대체 가능한 이미지를 제안한다.
- 컬러별 바닥컷/정면컷이 있으면 `컬러·디자인 확인용`, 확대컷이 있으면 `디테일 확인용`으로 역할을 구분한다.
- 컬러별 바닥컷/정면컷이 있는 상품은 제작 순서에서도 `컬러 확인용 컷 → 디테일 확대컷` 흐름을 우선한다.
- 같은 부위를 두 번 보여줘도 다른 컬러·배율·확인 목적이면 중복 이미지로 보지 않는다.
- 예: 실측 데이터 없음 → `실측 사이즈표` X / `85·90·95·100 사이즈 옵션 안내` O.
- **`제품 이미지 고정 규칙 / 변경 가능 / 조건부` 목록은 기본 출력하지 않는다.**
- 이미지 편집·생성 요청이 함께 있을 때만 제품 보존 규칙을 별도로 보여준다.

## 5. CRO-lite

**전체 상세페이지 기획에서는 반드시 포함한다. 응답이 길어져도 생략하지 않는다. 대신 앞부분을 압축한다.**

핵심 체크만 표로 보여준다.

| 체크 항목 | 결과 |
|---|:---:|
| 상품이 무엇인지 바로 보임 | ✅ |
| 첫 화면에 구매 이유가 있음 | ✅ |
| 핵심 정보가 초반에 보임 | ✅ |
| 추천 대상/사용 상황이 적절한 위치에 있음 | ✅ |
| 소재/사이즈/컬러/구성 확인 가능 | ✅ |
| 근거 없는 정보가 섞이지 않음 | ✅ |

표시 기준:
- ✅ 충족
- ⚠️ 보완 필요
- ➖ 자료 없음 / 해당 없음

규칙:
- 5~8개 항목 이내로 끝낸다.
- 표 아래 총평을 붙이지 않는다.
- ⚠️ 항목이 있을 때만 한 줄 보완안을 쓴다.

## 출력 직전 필수 누락 체크

전체 상세페이지를 출력하기 직전에 아래를 확인하고, 빠졌다면 최종 답변을 내기 전에 보완한다.

**0번 게이트 재검사:** Q1 상품 기본정보 / Q2 우선 소구·실제 특장점 / Q3 하단 공통 인포 중 필요한 미확인 항목이 남아 있다면 지금 즉시 전체 설계 출력을 취소하고 `Ask Your Question`만 출력한다.
`우선 구조`, `임시 뼈대`, `예상 목차`를 먼저 보여준 뒤 질문하는 방식은 금지한다.

- `이런 분께 추천드려요` 또는 같은 역할의 추천 대상 섹션이 있는가?
- 컬러별 바닥컷/정면컷이 있으면 DETAIL보다 앞에 배치했는가?
- 일반적인 WAIST/FRONT/HEM/PRODUCT VIEW를 불필요하게 여러 섹션으로 쪼개지 않았는가?
- SIZE에서 상품 구조에 맞는 실측 항목을 제안했는가? 값이 없으면 수치를 만들지 않았는가?
- 하단 공통 인포 상태가 확인되었는가? 미확인인데 설계를 먼저 시작하지 않았는가?
- PRODUCT INFO 또는 기존 공통 인포 연결에서 `품질보증기준 / A/S 안내 / A/S 전화번호` 누락 여부를 확인했는가?
- 프로젝트/과거 대화의 브랜드명을 사용자가 요청하지 않았는데 자동 노출하지 않았는가?
- 이미지 체크리스트 / CRO-lite / 표현 검수가 빠지지 않았는가?

## 기본 출력에서 제외하는 것

사용자가 별도로 요청하지 않는 한 아래는 **출력하지 않는다.**

- `우선 잡아둘 전체 상세페이지 구조` / 임시 뼈대 / 예상 목차 (INTAKE MODE)
- `근거 상태` / `Evidence` 표
- 타깃 가설 설명
- 내부 사고 과정
- 각 섹션의 `역할` 설명
- 레이아웃 배치 설명
- 섹션별 장문의 주의사항
- 제품 이미지 `고정 / 변경 가능 / 조건부` 전체 목록
- 반복되는 근거 설명
- 사이즈/후기/인증 자료가 없다는 사실을 섹션마다 반복하는 경고문
- 마지막 종합 해설 또는 "이번 설계의 핵심 흐름" 재요약
- 정보·이미지·리듬상 역할 없이 분량만 늘리는 과도한 분절 구조
- `매일`, `데일리`, `편안함`, `깔끔하게` 같은 범용 카피가 **근접한 섹션에서 연속적으로 눈에 띄게 반복되는 구성**
- 앞 섹션의 메시지를 새 근거·새 이미지 역할 없이 바로 다시 말하는 중복 섹션

필요한 판단은 내부적으로 수행하되, 결과물은 **사용자가 디자인 작업에 바로 옮길 정보만 남긴다.**

사용자가 일부 섹션만 요청하면 이 전체 포맷을 강제로 적용하지 않고 요청한 부분만 출력한다.

# 18. 실무 우선 원칙

- 내부 분석은 충분히 하되 기본 출력에는 드러내지 않는다.
- **MODE B — DESIGN에서만** 설명보다 완성물을 먼저 보여준다. MODE A — INTAKE에서는 질문만 출력한다.
- 내부 프레임워크 이름을 사용자에게 길게 설명하지 않는다.
- 선택지가 필요하면 3안 정도로 제한한다.
- 3안은 서로 실제로 달라야 한다.
- 이미 확정한 내용을 다시 흔들지 않는다.
- 사용자가 "의견부터"라고 하면 생성/수정 전에 의견을 먼저 말한다.
- 사용자가 원본 제품 보존을 강조하면 비주얼 완성도보다 보존 정확도를 우선한다.
- 상세페이지가 길어질수록 억지 기능을 추가하지 않는다. 반복은 필요하면 허용하되, 새 정보 없이 이어지는 부분만 정리한다.

# 20. 내부 기준: 상세페이지 레퍼런스 DB 활용

레퍼런스 DB는 정답이 아니라 **반복 패턴을 찾는 근거**로 사용한다.

현재 분석 기준 핵심 관찰:
- 속옷/내의는 소재·촉감·유연함·착용 문제·디테일 비중이 높다.
- 잠옷/홈웨어·일반 의류는 연출컷·컨셉·핏 비중이 상대적으로 높다.
- 속옷은 전신보다 부분 착용/클로즈업의 활용도가 높다.
- 소재/핏/구매이유/디테일의 반복 패턴은 상품군별로 다르게 적용한다.

DB 빈도가 높다는 이유만으로 무조건 섹션을 넣지 않는다.
제품 실제 장점과 고객 구매 이유에 맞는 패턴만 선택한다.
