# 소재 캐기

## 이 스킬이 답하는 것 / 답하지 않는 것

| | |
|---|---|
| ✅ **답한다** | **어디서** 캐나 · **무엇을** 소재로 보나 · **어떻게 골라** 쌓나 · **두 번 캐는 걸** 어떻게 막나 |
| ❌ **답하지 않는다** | 그 소재로 글을 어떻게 쓰나 → **글쓰기 스킬에 넘긴다** |

**이 스킬의 전제는 하나다.**

> **소재는 새로 만드는 게 아니라 이미 있는 것을 못 찾는 것이다.**

하루에 나눈 대화 안에 쓸 거리가 들어 있는데, 다음 날이면 잊는다.
이 스킬은 **그 대화를 다시 읽어 건져 올린다.**

---

## 시작하기 전에 ① — 재료 폴더를 찾는다

**아래 순서로 찾는다. 앞 순위에서 찾으면 거기서 멈추고 뒤는 안 본다.**

1. 지금 작업 중인 폴더의 **`kara-os-private/`**
2. 지금 작업 중인 폴더의 `sns-writing-private/` ← 예전 이름. 쓰던 사람은 그대로 잡힌다
3. 지금 작업 중인 폴더의 **그 밖의 `-private/` 폴더** (1·2번 이름은 **빼고** 센다)
4. `~/kara-os-private/`

🔴 **같은 순위에서 둘 이상 나오면 고르지 말고 묻는다.** (3순위에서만 생긴다.) 남의 재료 폴더를 말없이 읽어오면 안 된다.

> 🔑 **작업 폴더에 따라 잡히는 보관소가 다르다.** 시험 폴더에서 돌리면 시험 보관소, 평소 폴더에서 돌리면 진짜 보관소가 잡힌다.
> 그래서 **찾은 보관소의 전체 경로를 0단계 질문에 같이 적는다.**

| 파일 | 무엇 | 이 스킬이 하는 일 |
|---|---|---|
| `material-stash.md` | **소재 보관소** | 고른 것만 **넣는다** (4단계) |
| `who-i-am.md` | 글쓴이가 누구인지 | **읽는다.** 관심 없는 주제를 걸러낸다 |
| `my-voice.md` | 어투와 금지어 | 있으면 읽는다 |

## 🧪 시작하기 전에 ② — 이 보관소가 「시험용」인지 본다

🔑 **소재 보관소 파일의 맨 위 다섯 줄을 먼저 읽는다.**
거기에 **`시험용`·`테스트`·`가짜`** 라는 말이 있으면 **시험용 보관소다.**

그때는 **0단계 질문에 함께 적어 한 번에 묻는다** (따로 멈추지 않는다).

**왜 필요한가:** 스킬을 시험하려면 **비어 있는 보관소**가 있어야 한다.
그런데 재료 폴더 이름은 규칙상 **둘 다 `kara-os-private`** 이어서 이름으로는 구별이 안 된다.
사람이 기억하는 것으로는 못 막는다 — **파일 안에 적혀 있어야 막힌다.**

🔴 **시험용이면 같은 폴더의 `who-i-am.md` 도 가짜일 수 있다.** 시험 보관소는 대개 **가상 인물**로 채워져 있다.
그걸로 진짜 대화를 거르면 기준이 엉뚱해진다 — 가상 인물의 「제품 이름 금지」가 진짜 소재 3개를 막은 적이 있다.
그래서 **어느 `who-i-am.md` 로 거를지 경로를 밝히고 묻는다** — 이것도 0단계 질문에 함께 넣는다.

**진짜 재료 폴더 위치는 이렇게 찾는다.**

| 순서 | 어디서 |
|---|---|
| ① | 시험 보관소 **맨 위 다섯 줄**에 적힌 경로 — 예: *「진짜는 `~/…/material-stash.md`」* → 그 파일이 든 **폴더의 `who-i-am.md`** |
| ② | ①이 없으면 **묻는다.** 짐작해서 다른 폴더를 뒤지지 않는다 |

## 시작하기 전에 ③ — 없으면 직접 만들어 준다

🔴 **사용자에게 `mkdir` 을 시키지 않는다.** 어디서 실행하느냐에 따라 엉뚱한 곳에 생긴다.
**지금 작업 폴더가 어디인지는 이 스킬이 안다.** 그러니 이 스킬이 만든다.

만들 때는 `sns-writing` 스킬과 **같은 폴더 하나**를 쓴다. 스킬마다 따로 만들지 않는다.
🔴 **있는 파일은 절대 덮어쓰지 않는다.** 없는 것만 채운다.
깃으로 관리되는 폴더면 `.gitignore` 에 `*-private/` 를 넣을지 **묻는다.**

**재료 폴더가 없어도 그냥 진행한다.** 캔 결과를 화면에 보여주고, 끝난 뒤 *"보관소를 만들어 둘까요?"* 를 **한 번만** 제안한다.

## 🔴 0단계 · 어디서 캘지 먼저 묻는다

**이 단계를 건너뛰면 안 된다.** 이 스킬은 사람의 대화 기록을 읽는다.

### 먼저 목록을 만들어 보여준다

대화 기록은 여기에 쌓인다.

```
~/.claude/projects/<폴더이름>/<세션번호>.jsonl
```

🔴 **두 번에 나눠 묻는다. 고르기 전에는 대화 파일을 열지 않는다.**

| 차례 | 보여주는 것 | 파일을 여나 |
|---|---|---|
| **첫 질문** | **폴더 목록** — 폴더 이름 · 대화 파일 수 · 크기 · 파일 수정 날짜 | ❌ **안 연다.** 파일 목록과 크기만 본다 |
| **두 번째 질문** | 고른 폴더 안의 **창 목록** — 창 제목 · 마지막으로 말한 시각 · 말 수 | ⭕ **고른 폴더만** 연다. 글자는 화면에 내지 않고 **세기만** 한다 |

**왜 나누나:** 창 목록을 만들려면 마지막으로 말한 시각과 말 수를 세야 하고, 그러려면 **파일을 열어야 한다.**
한 번에 창 목록부터 보여주면 **고르기 전에 모든 창을 여는 것**이 된다 — 「묻지 않고 읽지 않는다」와 부딪힌다.

**첫 질문의 모양**

```
| # | 폴더 | 대화 파일 | 크기 | 파일 수정 |
|---|---|---|---|---|
| 1 | work-app     | 12개 |  96MB | 오늘 |
| 2 | side-blog    |  4개 |  21MB | 어제 |
| 3 | company-docs 🔒 |  6개 |  40MB | 5일 전 |

어느 폴더의 창을 볼까요? (번호 여러 개 가능)
🔒 는 경계 폴더입니다 (사용자가 말했거나 who-i-am.md 에 적힌 곳). 목록에만 올리고 열지 않습니다.
⚠️ 「파일 수정」은 마지막 대화 시각이 아닙니다. 창 목록에서 정확한 시각을 보여드립니다.
```

🔴 **폴더 이름만으로는 고르기 어렵다 — 그래서 두 번째 질문이 「창」 단위다.**

| 이유 | 실제로 겪은 것 |
|---|---|
| 폴더 이름은 사람이 못 알아본다 | 기록 폴더 이름은 `-Users-(사용자이름)-work-app` 같은 모양이고, 파일 이름은 `3f9a1c2e-…` 같은 세션번호다. 보고 *"이게 뭐니?"* 가 나왔다 |
| **폴더 ≠ 주제** | 한 폴더 안에 서로 다른 일의 창이 여러 개 섞여 있었다. 창을 연 뒤 다른 폴더로 옮겨가도 기록은 **처음 폴더**에 남는다 |
| 파일 수정 시각은 「마지막 대화」가 아니다 | 대화가 끝난 창도 제목 같은 **꼬리 정보**가 붙어 수정 시각이 5시간 뒤로 찍혔다 |

**만드는 법** — 파일(`.jsonl`) 하나가 창 하나다.

| 칸 | 어디서 뽑나 |
|---|---|
| 창 제목 | 줄 안의 `customTitle` → 없으면 `aiTitle` · **마지막 값**을 쓴다. 둘 다 없으면 **「(제목 없음) · 처음 말한 날짜」** — 🔴 **대화 글자를 목록에 내지 않는다** |
| 마지막으로 말한 시각 | 1단계 거르기를 통과한 **사용자 말 중 가장 늦은 `timestamp`** (한국 시각). **파일 수정 시각을 쓰지 않는다** |
| 말 수 | 같은 방법으로 센 사용자 말 개수. 기간을 아직 안 골랐으니 **최근 3일**로 센다 |

**마지막으로 말한 시각이 늦은 창부터** 보여준다.

```
| # | 창 제목 | 폴더 | 마지막으로 말한 시각 | 최근 3일 말 수 |
|---|---|---|---|---|
| 1 | 온보딩 화면 개편   | work-app  | 오늘 18:20 | 41 |
| 2 | 사용자 인터뷰 준비 | work-app  | 오늘 11:05 | 17 |
| 3 | 블로그 초안        | side-blog | 어제 23:40 | 9 |
```

**그리고 한 번에 묻고 멈춘다 (두 번째 질문).** 시작 ①·②에서 알게 된 것도 **여기에 모아** 묻는다.

```
📂 넣을 보관소: /전체/경로/kara-os-private/material-stash.md
   (🧪 시험용으로 표시돼 있습니다 — 진짜가 아니어도 계속할까요?)       ← 시험용일 때만

① 어느 창에서 캘까요? (번호 여러 개 가능)
② 기간은? — 지난번 캔 곳 이후 (work-app 09-12 21:14:05 뒤) / 오늘 / 어제부터 / 최근 3일
③ 걸러내기는 어느 「나는 누구인가」로 할까요?                          ← 시험용일 때만
   ㄱ) (시험 폴더)/who-i-am.md   ㄴ) (진짜 재료 폴더)/who-i-am.md
```

🔴 **보관소에 「마지막으로 캔 곳」 표시가 있으면 기간의 첫 선택지를 「지난번 캔 곳 이후」로 둔다.** 5단계와 이어지는 자리가 여기다.

**고른 폴더마다 표시가 있기도 하고 없기도 하면 폴더별로 한 줄씩 보여주고 묻는다.**

```
② 기간은?
   work       지난번 캔 곳 이후 (09-12 21:14 뒤)  ← 표시 있음
   side-blog  표시가 없습니다 — 오늘 / 어제부터 / 최근 3일 중에서 골라 주세요
```

### 🔴 답이 빠지거나 흐릿하면 — 알아서 정하지 않는다

**창과 기간이 둘 다 정해지기 전에는 대화 파일을 읽지 않는다.** 스킬이 대신 고르지 않는다.

| 받은 답 | 하는 일 |
|---|---|
| 창 번호만 (`3`) | **빠진 것만 다시 묻고 멈춘다** — *"창은 3번으로 받았습니다. **기간이 빠졌습니다.** 오늘 / 어제부터 / 최근 3일 중에 골라 주세요. 고르시기 전엔 읽지 않습니다."* |
| 기간만 (`어제부터`) | 같은 방식으로 **창을 다시 묻는다** |
| 「응」·「다」·「전부」·「아무거나」 | 「전부」로 읽지 않는다. **무엇을 뜻하는지 되묻는다** — *"창 19개 전부, 기간 전체라는 뜻일까요? 양이 많아 아래 한도에 걸립니다."* |
| 「알아서 해」 | **최근 3일**을 제안하고 **답을 받은 뒤** 읽는다 — *"최근 3일로 하겠습니다. 괜찮으면 「응」이라고 해 주세요."* |

> **왜:** 시험에서 창 번호만 답했더니 스킬이 기간을 스스로 「최근 3일」로 정하고 읽었다.
> 이번엔 사흘이라 괜찮았지만, 「전부」였다면 **몇 주 치 대화를 묻지 않고 읽는 것**이 된다 — 「묻지 않고 읽지 않는다」와 부딪힌다.

### 🔴 처리 한도 — 넘으면 읽기 전에 멈추고 알린다

**창과 기간이 정해지면, 글자를 읽기 전에 양부터 센다.** 1단계의 거르기를 **세기만** 하고 내용은 화면에 내지 않는다.
아래 셋 중 **하나라도 넘으면 멈춘다.**

| 한도 | 값 |
|---|---|
| 고른 창 | **5개** 넘음 |
| 기간 | **7일** 넘음 |
| 줄인 뒤 사용자 말 | **150KB** 넘음 |

```
⚠️ 양이 많습니다 — 아직 읽지 않았습니다
   창 6개 · 기간 12일 · 사용자 말 412개 (약 180KB)
   걸린 한도: 창 5개 · 기간 7일 · 150KB

   "기간 줄여 — 최근 3일"   → 줄여서 다시 셉니다
   "창 2, 3번만"            → 줄여서 다시 셉니다
   "그래도 해"              → 이대로 읽습니다 (오래 걸리고, 후보가 많아 고르기 어렵습니다)
```

**「그래도 해」라고 분명히 답했을 때만** 한도를 넘겨 읽는다. 흐릿한 답은 위 표대로 되묻는다.

> **숫자는 출발점이다.** 사흘치 여러 창이 대개 50~100KB 였고(1단계), 한 판 시험은 30KB 였다. 그 위로 여유를 둔 값이다.
> 쓰면서 너무 자주 걸리거나 안 걸리면 이 표만 고친다.

### 🔴 절대 지키는 것 세 가지

1. **묻지 않고 읽지 않는다.** 「전부 다 훑어보겠습니다」를 먼저 하지 않는다. 첫 질문 전에는 **어떤 대화 파일도 열지 않는다**
2. **무엇을 읽었는지 밝힌다.** **창 제목**과 기간을 결과에 적는다
3. **경계를 그은 폴더는 목록에 올리되, 고르기 전엔 열지 않는다**
   일 관계로 갈라둔 폴더(회사 과제·남과 같이 쓰는 저장소)가 그렇다.
   **경계인지는 스킬이 짐작하지 않는다** — 사용자가 말했거나 `who-i-am.md` 에 적힌 폴더만 경계로 본다.
   그 밖에는 첫 질문에서 고르는 것으로 대신한다

> **왜 이렇게까지 하나:** 대화 기록에는 비밀번호·고객 이름·아직 안 낸 기획이 섞여 있다.
> 소재를 캐다가 그것까지 끌어오면 **소재 보관소가 유출 통로가 된다.**

## 1단계 · 읽을 수 있는 크기로 줄인다

🔴 **대화 파일을 통째로 읽지 않는다.** 하나가 **70MB** 인 것도 있다. 열면 기억이 한 번에 꽉 찬다.

**필요한 것은 「사용자가 한 말」뿐이다.** 답변은 안 읽는다.

🔴 **파일이 작아도 통째로 열지 않는다.** 읽기 도구로 대화 파일을 열면 답변 줄까지 화면에 지나간다.
언제나 **아래 거르기를 거친 사용자 말만** 꺼내 읽는다 — 1KB 짜리 파일이어도 같다.
(시험에서 *"두 파일이 워낙 작아서 파일 전체를 열었다"* 가 실제로 나왔다.)

| | |
|---|---|
| 원본 | 한 폴더 대화 22개 · **176MB** |
| 사용자 말만 뽑으면 | **246KB** (0.14%) — 아래 거르기를 다 한 값 |
| 두 폴더 25개에서 사흘치만 자르면 | 말 196개 · **80KB** |

> ⚠️ 거르기 전에는 **1.35MB** 였다. 그중 약 **1.1MB 가 사용자 말이 아니었다** (스킬 설명서·압축 요약).

**왜 사용자 말만으로 충분한가:** 소재는 **겪은 사람이 한 말** 안에 있다.
*"3번 넣었는데 3번 다 실패했어"* 는 사용자가 한 말이다. 답변은 그걸 정리한 것뿐이다.

**뽑는 법** — 한 줄이 JSON 한 덩어리다. `type` 이 `user` 인 것만 골라 `message.content` 의 글자를 잇는다.

🔴 **`type` 이 `user` 라고 전부 사용자 말이 아니다.** 아래를 **전부** 버린다.

| 버리는 것 | 알아보는 법 | 안 버리면 |
|---|---|---|
| 스킬 설명서 · 지침 전문 | 줄에 `"isMeta": true` | 설명서 문장이 소재 후보로 올라온다 |
| 대화 압축 요약 | 줄에 `"isCompactSummary": true` | 요약문이 사용자 말처럼 섞인다 |
| 도구 결과 | `content` 안에 `tool_result` | 명령 출력이 섞인다 |
| 시스템 알림 | 글자가 `<` 로 시작 | 알림이 섞인다 |
| 중간에 멈춘 표시 | `[Request interrupted` 로 시작 | 의미 없는 줄이 섞인다 |

🔴 **시각은 한국 시각으로 바꾼 뒤 자른다.** 기록의 `timestamp` 는 **영국 기준(UTC, 끝에 `Z`)** 이다.
그대로 「오늘」을 자르면 **오전 9시 전 대화가 어제로 들어간다.** 사용자가 있는 곳의 시각으로 바꾼다.

🔴 **같은 말은 한 번만 남긴다.** 두 가지 경우가 있다.

| 경우 | 왜 생기나 | 묶는 법 |
|---|---|---|
| 이어 연 창 | 창을 이어 열면 앞 대화가 **새 파일에 복사**된다 (파일 3개에 같은 말 14개) | 시각·내용이 같으면 하나로 |
| 같은 요청을 다시 보냄 · 두 창에 붙여 넣음 | 멈췄다 다시 보내거나, 마감이 겹친 날 흔하다 | **시각이 달라도 내용이 글자까지 같으면** 하나로. 창 이름은 둘 다 적는다 |

🔴 **짧은 말(30자 미만)은 내용이 같아도 묶지 않는다.**
「오늘은 여기까지」 같은 짧은 말은 **반복 자체가 소재**일 수 있다 — 밤늦게 창 네 개에 몇 분 간격으로 친 같은 짧은 말을
묶었더니 **4번이 2번으로 줄어 소재가 사라졌다** (시험에서 실제로 걸림).

**글자가 몇 개만 다른 말은 기계로 묶지 않는다.** 후보를 보여줄 때 *"○번과 비슷합니다"* 로 짚는다 (3단계).

```
· 시각을 앞에 남긴다 — 나중에 「며칠자 소재」로 쓴다
· 🔴 기간으로 먼저 잘라낸다. 사흘치 여러 창이면 대개 50~100KB 다
```

> **`daily-log` 같은 도구가 있으면 써도 된다.** 없어도 된다 — **이 스킬은 혼자 돈다.**
> 남이 받아 썼을 때 도구가 없어서 멈추면 안 된다.

## 2단계 · 기준에 걸린 것만 뽑는다

🔑 **이 스킬의 심장이다.** 기준이 없으면 *"여러 번 시도했으나 실패"* 같은 맹물이 쌓인다.

### 기준 다섯 가지

| # | 기준 | 줄임말 | 실제로 걸린 예 |
|---|---|---|---|
| 1 | **숫자가 남았나** | 숫자 | *"3번 넣었는데 3번 다 실패. 크레딧 0"* · *"33.55초 → 34.82초"* |
| 2 | **예상과 달랐나** | 반전 | *"짧아질 거라던 내 예상이 틀렸다"* · *"만들 필요가 없었다"* |
| 3 | **아직 안 끝났나** | 진행중 | *"아직 아무도 안 썼다"* — 다음 글의 예고편이 된다 |
| 4 | **겪은 사람만 아는가** | 겪은이 | *"항목 이름이 「화면 기록」이 아니라 「화면 및 시스템 오디오 녹음」이었다"* |
| 5 | **누가 뭐라고 말했나** | 대사 | *"00시 33분에 **사람이 쓴** 답장이 왔다"* · 남의 말이면 이름을 빼고 요지만 |

**후보 표에는 번호가 아니라 줄임말로 적는다.** 후보 번호와 기준 번호가 섞이면 사람이 헷갈린다.

**5번이 왜 있나:** 글을 여는 가장 안정적인 방법이 **실제로 한 말을 따옴표로 먼저 놓는 것**이다.
그런데 1~4번은 전부 **「사실이 어떤 모양인가」**를 본다. **누가 뭐라고 했는가**를 보는 칸이 따로 있어야 한다.

> 🔴 **대사는 마음대로 옮기지 않는다.** 남이 한 말이면 **이름을 빼고 요지만** 적는다.
> 그대로 쓰려면 그 사람의 허락이 필요하다. **내가 한 말은 그대로 써도 된다.**

### 걸린 개수로 순서를 매긴다

**문턱으로 쓰지 않고 점수로 쓴다.** 하나만 걸려도 후보에는 올린다.

```
2개 이상 걸림  →  ⭐ 위로 올린다
1개 걸림       →  아래. 「약하다」고 적어둔다
0개            →  안 내놓는다
```

**어느 기준에 걸렸는지 후보마다 적는다.** 사용자가 *"대사 기준은 빼"* 라고 할 수 있어야 한다.
**기준을 늘리거나 줄이는 것은 이 표에 한 줄 더하거나 지우면 된다.**

### 🔴 걸러내는 것

- `who-i-am.md` 에 **「절대 쓰고 싶지 않은 주제」**로 적힌 것
- **남의 말** — 채팅방·댓글에서 본 남의 문장은 **이름을 빼고 요지만.** 그대로 옮기려면 허락이 필요하다
- **비밀번호·열쇠값·고객 이름·주소·전화번호** — 보이면 소재로 만들지 않고 **본 사실만 알린다**
- **이미 보관소에 있는 것** — 두 겹으로 막는다

  | 겹 | 무엇으로 | 하는 일 |
  |---|---|---|
  | 시각 | 5단계 「마지막으로 캔 곳」 표시 | **이미 읽은 말**을 다시 안 읽는다 |
  | 내용 | 후보마다 **보관소의 줄과 맞대 본다** — 같은 숫자 · 같은 사건이 있나. 🔴 **낱말이 달라도 같은 일이면 같다** — *「5명 중 0명이 안 눌렀다」* 와 *「아무도 안 눌렀다」* 는 같은 사건이다. 글자 찾기로 판정하지 않는다 | 있으면 **빼지 않고** 후보 옆에 *"보관소 ○번째 줄과 비슷합니다"* 로 짚는다. **합칠지 뺄지는 사람이 정한다** |

  시각 겹만으로는 부족하다 — **다른 창에서 같은 일을 다시 얘기하면** 새 말로 잡힌다.
- 🔴 **AI와의 소통 실수 · AI가 틀린 일** — 기본으로 뺀다

  AI가 확인 없이 결론을 내렸거나, 서로 말이 어긋나서 생긴 일은 **숫자·대사가 있어서 기준에 잘 걸린다.**
  그런데 남이 읽으면 **「그 사람 도구 설정 문제」로 끝난다.** 가져갈 게 없다.

  ```
  빼는 예   "AI가 파일 이름을 잘못 알아듣고 다른 파일을 고쳤다"  ·  "답이 길어서 절반만 읽었다"  ·  "아까 정한 걸 AI가 다르게 기억했다"
  올리는 예 "대화창 기억이 거의 찼다는 경고를 보고 → 90%에서 끊는 습관을 들였다"  ← AI를 오래 쓰는 사람은 누구나 겪는다
  ```

  **예외 — 두 질문에 모두 「예」일 때만 올린다.**

  | 질문 | 「아니오」인 예 | 「예」인 예 |
  |---|---|---|
  | ① **내 설정·내 대화 방식 탓이 아니라, 그 도구를 쓰는 누구에게나 생기나?** | 파일 이름을 잘못 알아들음 — 내가 이름을 모호하게 말한 탓 · 절반만 읽음 — 답을 길게 받은 탓 | 대화창 기억이 거의 참 — 오래 쓰면 누구나 |
  | ② **읽는 사람이 따라 할 행동이 하나 남나?** | 「헷갈렸다」로 끝남 | 「90%에서 마감한다」 · 「마지막 고르기는 사람이 한다」 |

  **하나라도 「아니오」면 뺀다.** 올릴 때는 후보 옆에 **남는 행동을 한 줄** 적는다.
  판단이 애매하면 **빼지 말고** *"AI 소통 실수라 뺄 수도 있습니다"* 로 짚고 사람에게 넘긴다.

> **왜 이 줄이 생겼나:** 시험에서 후보 17개 중 ⭐가 15개였는데, 사용자가 진짜 소재로 고른 건 **3개**였다.
> 기준 다섯 가지는 **「글에 쓸 신호가 있나」** 만 보고 **「읽는 사람이 가져갈 게 있나」** 는 안 본다. 이 줄이 그 빈틈을 막는다.

## 3단계 · 번호를 붙여 보여주고 멈춘다

🔴 **여기서 멈춘다. 바로 파일에 쓰지 않는다.**

```
| # | 소재 | 남은 숫자 / 각도 | 걸린 기준 | 어디서 |
|---|---|---|---|---|
| ⭐ 5 | 인터뷰 신청 폼에 들어온 4명 중 3명은 내가 시험 삼아 넣은 것 | 4명 중 3명 | 숫자·반전·진행중 | 사용자 인터뷰 준비 · 09-13 |
| ⭐ 6 | 새로 만든 버튼을 사용자 테스트 5명 중 아무도 안 눌렀다 | 5명 중 0명 | 숫자·반전 | 온보딩 화면 개편 · 09-12 |
| 7 | 회의에서 아무도 안 물어본 자료를 또 준비해 갔다 | — | 겪은이 · **보관소 2번째 줄과 비슷합니다** | 온보딩 화면 개편 · 09-13 |
```

**어디서** 칸에는 **창 제목**을 적는다. 폴더 이름이나 세션번호를 적지 않는다.

**후보 번호는 보관소에 이미 있는 소재 다음부터** 붙인다. 세는 것은 **소재 한 건 = 한 줄**이다.

| 보관소가 | 세는 것 |
|---|---|
| 번호 붙은 표 | 가장 큰 번호 (15번까지 있으면 16번부터) |
| 번호 없는 목록 | `- ` 로 시작하는 줄 수 (7줄이면 8번부터). **파일 전체 줄 수가 아니다** — 제목·빈 줄·표시 줄이 섞여 있다 |

이 번호는 **고르는 동안만 쓰는 이름표**다 — 보관소에 넣을 때는 4단계대로 보관소 형식을 따른다.

**표 바로 아래에 「지금 할 수 있는 것」을 반드시 붙이고 멈춘다.** 표만 내놓고 끝내면 사용자는 *"이제 뭘 하지? 가만히 있으면 어떻게 되지?"* 에서 막힌다.

```
지금 할 수 있는 것
  "16, 18번 넣어"        → 보관소에 두 줄 더합니다 (원래 줄이 다 남았는지 확인해 보여드립니다)
  "17번은 이렇게 고쳐서"  → 고친 문장으로 넣습니다
  "전부 다"              → 후보 14개를 전부 넣습니다
  "오늘은 없다"           → 아무것도 안 넣고, 「여기까지 읽음」 표시만 적습니다

⚠️ 아무 말 없이 창을 닫으면 → 아무것도 저장되지 않습니다. 다음에 캘 때 같은 후보가 다시 나옵니다
```

🔴 **사용자에게 숙제를 주지 않는다.** *"진짜 소재 번호를 알려 주시면 기준을 다듬겠습니다"* 같은 말을 붙이지 않는다.
기준을 고치는 건 **스킬을 만드는 사람의 일**이다. 쓰는 사람은 **넣을지 말지만** 정한다.

### 🧪 「넣지 마」·「시험이야」라고 했을 때

사용자가 **어느 단계에서든** 이렇게 말하면 이번 판은 **읽기만** 한다.

| | |
|---|---|
| 보관소 | **한 글자도 안 쓴다.** 5단계 표시도 안 적는다 |
| 증거 | 캐기 **전후로 보관소 지문(sha256)을 떠서** 같다는 것을 보여준다 |
| 끝맺음 | 「지금 할 수 있는 것」 대신 이 한 줄로 닫는다 — *"시험이라 무엇을 고르셔도 넣지 않습니다. 보관소 그대로(지문 같음). 이대로 창을 닫으셔도 됩니다."* |

🔴 **「오늘은 없다」여도 5단계 표시는 갱신한다.** 읽은 건 읽은 것이다.
갱신하지 않으면 **다음에 같은 후보가 또 나온다.** 고른 게 일부여도 표시는 **읽은 끝까지** 옮긴다.

> **왜 기계가 정하지 않나:** 보관소가 스스로 적어둔 규칙이 있다 —
> *「3번 넣었는데 3번 다 실패」가 「여러 번 시도했으나 실패」보다 세다.*
> 이 차이는 기계가 못 잡는다. **마지막 한 칸은 사람이 본다.**

## 4단계 · 고른 것만 넣는다

🔴 **덮어쓰지 않는다. 줄을 더하기만 한다.**

### 어디에 넣나

| 보관소에 | 넣는 곳 |
|---|---|
| 맞는 칸이 있다 (진행 중 / 터진 문제 / 예상과 달랐던 것 / 겪은 사람만 아는 것 / 미정 …) | **그 칸 안에** 끼워 넣는다 |
| 맞는 칸이 없다 | **맨 아래** 새 줄로 |

칸 안에서 순서는 **보관소가 쓰던 순서**를 따른다 (최신이 위면 위에).

### 모양은 보관소를 따른다

| 보관소가 | 넣는 모양 |
|---|---|
| 번호 붙은 표 (`\| # \| 소재 \| …`) | **마지막 번호 다음부터** 빈 번호 없이 이어 붙인다. 후보 16·18번을 골랐으면 보관소에는 16·17번이 된다 — **바뀐 번호를 알려준다** |
| 번호 없는 줄 (`- 2026-09-08  …`) | **날짜 + 한 줄.** 번호를 새로 만들지 않는다 |

**어느 쪽이든 꼬리표를 끝에 남긴다** — 어느 창 · 며칠자에서 왔나.

```
| 16 | 새로 만든 버튼을 5명 중 아무도 안 눌렀다 | 5명 중 0명 | 온보딩 화면 개편 · 09-12 |
- 2026-09-12  새로 만든 버튼을 5명 중 아무도 안 눌렀다  ← 온보딩 화면 개편 · 09-12
```

### 🔴 넣기 전에 사본, 넣은 뒤에 대조

칸 안에 끼워 넣으면 **파일 중간을 고치는 것**이다. 실수로 원래 줄을 덮거나 지울 수 있다. 그래서 두 가지를 한다.

1. **넣기 전** — 보관소 파일의 사본을 떠 둔다 (임시 폴더에)
2. **넣고, 5단계 표시까지 갱신한 뒤** — 사본과 줄 단위로 맞대어 확인해 보여준다

「오늘은 없다」로 **표시만 갱신할 때도** 파일을 고치는 것이다. **똑같이 사본을 뜨고 대조한다.**

| 확인 | 기준 |
|---|---|
| 원래 줄 | **「마지막으로 캔 곳」 표시 줄을 뺀** 원래 줄이 **순서 그대로 전부** 남았나 |
| 표시 줄 | 폴더마다 **딱 한 줄**인가 (없거나 두 줄이면 실패) |

```
원래 17줄(표시 줄 2개 제외) → 전부 남음 · 순서 그대로 ✅
표시 줄: work-app 1 · side-blog 1 ✅
```

🔴 **왜 표시 줄을 빼나:** 5단계는 표시 줄을 **새 시각으로 바꾼다.** 옛 줄이 사라지는 게 정상이다.
빼지 않으면 대조가 **매번 「사라진 줄 있음」으로 실패**해서 넣을 때마다 되돌리게 된다 (시험에서 실제로 걸림).

**하나라도 사라졌으면 사본으로 되돌리고 그대로 알린다.** 넘어가지 않는다.

🔴 **다듬지 않는다.** 사용자가 한 말의 **거친 결을 그대로** 남긴다.
*"3번 넣었는데 3번 다 실패"* 를 *"반복 시도 끝에 실패"* 로 고치면 **소재가 죽는다.**

**쓴 뒤 무엇을 어디에 몇 줄 넣었는지 전체 경로로 보여준다.**

## 5단계 · 「어디까지 캤나」를 적는다

보관소 맨 아래에 한 줄을 둔다.

```
<!-- 마지막으로 캔 곳: work-app · 2026-09-12 21:14:05 까지 -->
```

🔴 **초까지 적는다.** 적는 값은 **이번에 읽은 마지막 말의 시각**(한국 시각)이다. 「지금 시각」이 아니다.
분까지만 적으면 **같은 분에 한 말**이 다음에 다시 잡히거나 빠진다 (시험에서 1개 걸림).
다음에 캘 때는 **이 시각보다 뒤인 말만** 읽는다.

**경우마다 이렇게 한다.**

| 경우 | 하는 일 |
|---|---|
| 새 표시 (초까지) `17:35:18` | 🔴 **말의 시각도 초 아래를 버리고** 비교한다. 초가 표시보다 **뒤**인 말만 읽는다 — 기록 시각엔 `17:35:18.937` 처럼 1000분의 1초가 붙어 있어서, 그대로 비교하면 **방금 캔 마지막 말이 다시 잡힌다** (시험에서 실제로 걸림) |
| **옛 표시 (분까지)** `17:35` | **그 분의 59초까지** 읽은 것으로 본다 → `17:35:59` 뒤만 읽는다. 갱신할 때 초까지 형식으로 바꾼다 |
| 고른 창에서 **읽은 말이 0개** | 표시를 **그대로 둔다.** 시각을 새로 지어내지 않는다 |
| 그 폴더를 이번에 **안 골랐다** | 표시를 **건드리지 않는다** |
| 🔴 **한 폴더에서 창을 일부만 골랐다** | 표시는 폴더 단위라 안 고른 창의 말까지 「읽음」이 된다. **갱신 전에 알리고 묻는다** — *"안 고른 창 ○개의 말도 다음부터 안 읽게 됩니다. 괜찮을까요?"* |

**다음에 캘 때 이 줄부터 읽는다.** 없으면 **같은 소재를 두 번 캔다.**

폴더가 여러 개면 폴더마다 한 줄씩. 🔴 **이 줄을 안 남기면 이 스킬은 쓸수록 나빠진다.**

## 원칙 다섯 가지

### 1. 자동으로 돌지 않는다

사람이 *"캐줘"* 라고 할 때만 돈다. 자동으로 쌓으면 **보관소가 쓰레기통이 된다.**
세션 마감 때 *"오늘 하나 건졌나요?"* 를 묻는 것까지가 이 스킬의 몫이다.

### 2. 묻기 전에 읽지 않는다

어느 창을 읽을지 **사람이 고른다.** 읽은 뒤에는 **무엇을 읽었는지 밝힌다.**

### 3. 덮어쓰지 않는다

보관소는 **쌓이는 파일**이다. 정리하고 싶어도 **묻고 나서** 한다.

### 4. 다듬지 않는다

거친 말이 센 말이다. 숫자는 **있는 그대로** 남긴다.

### 5. 두 번 캐지 않는다

「어디까지 캤나」 줄을 매번 갱신한다.

## 자주 막히는 곳

| 이럴 때 | 이렇게 한다 |
|---|---|
| 대화 파일이 너무 크다 | **기간으로 먼저 자른다.** 통째로 열지 않는다 |
| 후보가 30개 넘게 나왔다 | **기준이 3개 이상 걸린 것만 먼저 보여준다.** 나머지는 *"더 볼까요?"* |
| 후보가 0개다 | **그대로 말한다.** 억지로 만들지 않는다. *"오늘은 대화가 짧았습니다"* 도 답이다 |
| 보관소가 어디 있는지 모르겠다 | 재료 폴더 찾는 순서 4단계를 그대로 밟고, **둘 이상이면 묻는다** |
| 같은 소재가 이미 있는 것 같다 | **번호와 함께 짚어준다.** *"12번과 비슷합니다 — 합칠까요?"* |
| 시험용 보관소에 쓸 뻔했다 | 맨 위 다섯 줄에 「시험용」이 있으면 **0단계 두 번째 질문에 적어 묻는다** |
| 방금 캔 마지막 말이 또 나왔다 | 말의 시각에 붙은 **1000분의 1초를 안 버리고** 비교한 것이다 (5단계) |
| 창 목록을 만들다 모든 창을 열었다 | 0단계를 **두 번**에 나눈다. 폴더를 고른 뒤에만 연다 |
| 스킬 설명서 문장이 후보로 올라왔다 | `isMeta` · `isCompactSummary` 줄을 안 버린 것이다 (1단계) |
| 어제 한 말이 오늘로 잡혔다 | 시각을 **UTC 그대로** 자른 것이다. 한국 시각으로 바꾼다 |
| 같은 후보가 두 번 나왔다 | 이어 연 창 · 두 창에 붙여 넣은 말이다. **30자 이상이고 글자까지 같으면 하나로.** 짧은 말은 묶지 않는다 |
| 대조가 매번 「사라진 줄 있음」이다 | 「마지막으로 캔 곳」 표시 줄을 **빼고** 대조했는지 본다 (4단계) |
| 지난번 캔 말이 또 나왔다 | 표시가 **분까지만** 적힌 옛 형식이다. 그 분의 59초까지 읽은 것으로 본다 (5단계) |
| 목록에서 어느 창인지 모르겠다 | 폴더 이름·세션번호가 아니라 **창 제목**으로 보여준다 (0단계) |
| ⭐가 너무 많다 | 대개 **AI와의 소통 실수**가 섞인 것이다. 2단계 걸러내기를 다시 본다 |
| 넣다가 원래 줄이 사라졌다 | **사본으로 되돌리고 그대로 알린다** (4단계) |

## 소재가 모였으면 — 글쓰기로 넘긴다

이 스킬은 **글을 쓰지 않는다.**

| | |
|---|---|
| 글쓰기 스킬이 있으면 | 고른 소재를 넘긴다 — *"이 소재로 스레드 글 써줘"* |
| 여러 편으로 펼치려면 | 배치 스킬로 넘긴다 — *"이 소재로 신청까지 설계해줘"* |
| 둘 다 없으면 | 소재 표만 남기고 끝낸다. **그것으로도 쓸모가 있다** |

---

## 왜 「내 대화」에서 캐나

소재를 캐는 도구는 이미 여러 개 있다. 대개 **바깥**을 본다 — 남의 글, 경쟁사, 유행하는 주제.

**이 스킬은 안을 본다.**

| | 재료를 어디서 가져오나 |
|---|---|
| 바깥을 보는 도구 | 남의 글 · 레퍼런스 사이트 · 인터뷰 답변 — **따로 적어 넣어야 한다** |
| **이 스킬** | **이미 쌓인 내 대화** — 따로 적을 필요가 없다 |

**차이는 「따로 적을 필요가 없다」 하나다.** 소재를 쌓는 일이 실패하는 이유는 대개
좋은 일이 없어서가 아니라 **그때 적어두지 않아서**다. 대화는 이미 적혀 있다.
