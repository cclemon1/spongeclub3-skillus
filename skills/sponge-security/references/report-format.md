# 보고서 양식

스크립트가 마크다운 리포트를 만들지만, 사용자에게 **최종 보고**는 Claude 가 쓴다.
스크립트 출력을 그대로 붙이지 않는다 — 후보 목록을 읽고 판단한 결과를 쓴다.

## 스킬 심사 보고

```markdown
## 심사 결과: <스킬 이름>

**판정: 설치 권장 / 조건부 / 설치 비권장**

한 문단 — 이 스킬이 무엇을 하는지, 판정의 핵심 근거.

### 스폰지클럽 규범 대조
| 규범 | 결과 | 한 줄 |
|---|---|---|
| 키를 채팅으로 요청하지 않는다 | 통과 | 키가 필요한 화면은 사용자에게 넘긴다고 명시 |
| 데이터·배포를 삭제하지 않는다 | 위반 | `SKILL.md:41` "테스트 표를 drop 한다" |
| … | | |

### 확인된 위험
- (파일:줄) 무엇이 있고, 왜 문제이고, 실제로 어떤 피해로 이어지는지

### 정상으로 판단한 항목
- 스캐너가 잡았지만 문맥상 정상인 것들 (왜 정상인지 한 줄)

### 설치한다면
- 권한 제한, 처음 몇 번은 툴 호출을 하나씩 승인, 업데이트 시 재심사 등 구체적 조건

### 스캐너가 못 본 것
- 실행 시점 URL 로딩, 의존성, 다음 커밋
```

판정 기준:
- **설치 비권장** — 즉시 거절 항목이 하나라도 있거나, 설명과 실제 지시가 다르거나, 읽을 수 없는
  파일이 있거나, 규범 위반이 확정됐을 때
- **조건부** — 위험은 없지만 권한이 넓거나, 자동 push 처럼 사용자가 알고 써야 할 동작이 있을 때
- **설치 권장** — 규범 대조 전부 통과, 설명과 지시 일치, 출처 확인

## 공개 전 점검 보고

```markdown
## 공개 전 점검: <저장소> (<모드>)

**결론: push 가능 / 고치고 push / 멈춤**

한 줄 — 지금 당장 N · 이번 주 M · 나중에 K. 예외로 제외 X.

### 지금 당장 (push 전에)
- (파일:줄) 무엇 — 왜 — **누가** 고치나 (사용자: 재발급 / AI: 코드 수정)

### 이번 주
- …

### 나중에 / 넘긴 것
- 오탐으로 판단해 예외 등록한 것과 사유
- LOW 인데 그냥 두기로 한 것과 이유

### 저장소 밖에서 직접 확인할 것
- Vercel 환경변수 범위, Supabase Data API·anon REST, 공개 버킷, 어드민 시크릿 창, 방침 대조

### 통과
- 스크립트가 확인한 것 (.env 미추적, .gitignore 커버, 크론 시크릿, …)
```

**결론 기준**: 지금 당장이 0 이면 "push 가능"(이번 주 항목은 공개 후 고쳐도 되는 것만 남았을
때) 또는 "고치고 push"(이메일·주소처럼 공개 전에 빼는 편이 싼 것이 있을 때). 지금 당장이
있으면 "멈춤".

## 쓸 때 지키는 것

- 값을 옮겨 적지 않는다. 마스킹된 발췌(`AKIA…PLE (20자)`)까지만
- "안전합니다"를 근거 없이 쓰지 않는다. 통과한 항목을 나열하는 것이 근거다
- 사용자가 직접 할 일(재발급·삭제·대시보드)과 AI 가 승인받고 할 일을 구분한다
- 스캐너가 못 본 것을 마지막에 적는다. 통과처럼 보이면 안 된다
