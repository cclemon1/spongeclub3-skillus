점검 실행

공개 전 점검은 저장소를 읽기만 한다. 스킬 심사는 스킬 폴더·.skill 파일·git 주소를 받고, 아무것도 실행하지 않는다.

내 정보

여기 적은 값이 파일에 그대로 있으면 "지금 당장" 으로 잡는다. 이 목록은 이 PC 의 ~/.claude/sponge-security/config.json 에만 저장되고 어디로도 전송되지 않는다.
종류를 시크릿 값으로 고르면 값 자체는 저장하지 않고 SHA-256 해시만 남긴다 — 점검 때 파일 속 토큰을 해시해 대조한다. 프로젝트의 gitignore 된 .env.local·.env.prod 값은 등록하지 않아도 점검 때마다 자동으로 대조한다.

glob 한 줄에 하나 (예: docs/archive/**). 점검에서 제외된다.

예외 목록

오탐을 등록해 두면 다음 점검부터 "예외로 제외" 로 내려간다. 규칙은 * 로 전체, 파일은 glob(비우면 전체), 패턴은 발견 텍스트에 포함되는 문자열. 사유를 꼭 적는다 — 나중에 왜 넘겼는지 기억 못 한다.

기록

어떻게 쓰나

1. 내 정보를 먼저 채운다. 이메일·전화·이름·OS 계정명. "git · OS 계정에서 가져오기" 로 시작하면 빠르다.

2. push 하기 전에 점검한다. "공개 전 점검" → 폴더 → 점검. 지금 당장 이 0 이 될 때까지 push 하지 않는다. 이미 커밋된 시크릿은 지우는 게 아니라 재발급이 답이다.

3. 오탐은 예외로. 결과 카드의 "예외 등록" 에 사유를 적고 등록한다. 예외는 규칙+패턴+파일 단위라, 다른 파일에 같은 값이 새로 생기면 다시 잡힌다.

4. 내려받은 스킬은 설치 전에 심사한다. "스킬 심사" 에 폴더나 GitHub 주소. 자동 판정은 힌트고, SKILL.md 본문을 읽는 것이 심사다. 스폰지클럽 규범 대조표가 "확인 필요" 면 그 줄을 직접 읽는다.

5. Claude Code 에서: "편집기 열어줘" 라고 하면 이 화면이 뜬다. "스폰지보안으로 점검해줘", "이 스킬 안전해?", "깃허브 올려도 돼?" 라고 말하면 같은 스크립트가 돈다. 훅을 설치하면 git push · vercel 명령 직전에 자동으로 돈다.
